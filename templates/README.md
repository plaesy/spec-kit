# Templates

Reusable document skeletons for the Spec-Kit workflow. `template-registry.json` is the machine-readable registry (every shipped template must have an entry — `templates_drift_test.go` fails the build
otherwise); this file is the human index.

## Core workflow

| Template | Purpose |
|----------|---------|
| [constitution.template.md](constitution.template.md) | Project constitution — governing rules per active dimension (technical, design, business, product, marketing, legal, financial, management). Generated by `/start`, validated by `plaesy validate constitution`. |
| [spec.template.md](spec.template.md) | Feature specification |
| [plan.template.md](plan.template.md) | Implementation plan |
| [tasks.template.md](tasks.template.md) | Task breakdown |
| [spec-structure-folder.template.md](spec-structure-folder.template.md) | Recommended `.plaesy/specs/<feature>/` folder layout |
| [task-structure-guide.template.md](task-structure-guide.template.md) | Epic/story/checklist folder structure reference (**not** the implemented model — see note below) |
| [task-readme.template.md](task-readme.template.md) / [task-status.template.json](task-status.template.json) | Per-task README and status file reference (**not** the implemented model — see note below) |
| [status.template.md](status.template.md) | Project status dashboard |
| [context.template.md](context.template.md) | Session context skeleton for `.plaesy/context.md` |
| [state.template.json](state.template.json) | Autonomous-loop state (iteration, failure count, quality gates) read by `/loop` |
| [memory.template.md](memory.template.md) | Memory file skeleton for `.plaesy/memory/<topic>.md` |
| [instructions.template.md](instructions.template.md) | Skeleton for authoring a scoped `*.instructions.md` file — `applyTo` glob, rule + "why", and one worked example. Paired with `instructions/how-to-create-instructionsmd.instructions.md`, which carries the full guidance. |

**Note on task tracking**: the three templates above describe a richer
epic/story/JSON-status model that the `plaesy tasks` command does **not**
implement — it only moves flat `.md` files between
`.plaesy/tasks/{backlog,todo,doing,done,blocked}/`, with no epic/story
nesting and no JSON status fields populated or read. Treat these three templates
as a design reference for a possible future task model, not the current one;
the flat `.plaesy/tasks/{{STATUS}}/*.md` layout (see `.plaesy/instructions/tasks.md`)
is what `/implement`, `/continue`, and `/save` actually read and write.

## Conventions

- **Fill-ins use `{{NAME}}` or `{{NAME|default}}`, and nothing else.** This is
  not a style preference — it is the only form the validators can see. The
  unfilled-placeholder checks in `plaesy validate constitution` and the OOXML
  validators grep for `{{ ... }}`; a document generated from a template that
  used `{project_name}` or `<PROJECT_NAME>` sails past every one of them, so a
  template that was never filled in ships looking finished. `{{ }}` also cannot
  be confused with a markdown link, a Go template action, or a shell brace.
  **Binding for any template you create or edit.**

  Four syntaxes were in use across this directory, and only the first is
  checkable:

  | Syntax | Status |
  |--------|--------|
  | `{{NAME\|default}}` | **Canonical** — the only form validators can see |
  | `{lower_snake}` | Legacy, deprecated, invisible to validators |
  | `<angle_bracket>` | Legacy, deprecated, invisible to validators |
  | `[UPPER_SNAKE]` | Legacy, deprecated, invisible to validators |
  | `{a\|b\|c}` value enums | Legacy, deprecated — see note below |

  **The legacy migration IS done, and it is enforced rather than asserted.**
  The census below is generated from the same measurement the CI gate uses, so
  the two cannot disagree:

  | Measure | Value |
  |---------|------:|
  | Templates in this directory | 57 |
  | Legacy `[BRACKET]` / `{curly}` markers in prose | **0** |
  | Files with any legacy marker remaining | **0 of 57** |

  This was **1,201 legacy markers across 25 files** when the migration started.
  It is now zero, and `TestTemplateLegacyMarkersDoNotGrow`
  (`scripts/internal/quality/template_marker_ratchet_test.go`, baseline
  `scripts/template-marker-baseline.json`) fails the build if any template regains
  one. It counts **prose only** — fenced code blocks and inline code spans are
  excluded, because a `[Module]` inside a code sample is an illustration, not a
  slot — and it re-records with:

  ```bash
  go test ./internal/quality -run TestTemplateLegacyMarkersDoNotGrow -update-template-marker-baseline
  ```

  The `pendingSkeletonMigration` allowlist in
  `scripts/cmd/plaesy/placeholder_drift_test.go` is now **empty**: every template
  has at least one canonical fill-in, so there is no known file still short of the
  standard. It is kept as an empty map rather than deleted, because that list is
  how the next known gap gets recorded.

  **Converting these was not a regex job, and the reason is worth keeping.** A
  meaningful share of bracket tokens in this directory are *not* fill-ins —
  `[Ctrl+C]` and similar are keyboard shortcuts in `user-training-guide`, `[FAQ]`
  is a link, `{{ }}`-adjacent angle brackets are TypeScript generics. Every
  conversion needed an explicit per-instance decision. Do not bulk-replace.

  Tokens that look like deprecated fill-ins and genuinely must stay:

  | Token | File | Why it stays |
  |-------|------|--------------|
  | `<AuthResult>`, `<ComplianceStatus>`, `<string>`, `<boolean>`, `<void>` | `ci-cd-security.template.md` | TypeScript generics in a code example, not fill-ins |
  | `<feature>`, `<topic>`, `<angle_bracket>`, `<div>` | this file | The taxonomy table above, documenting the deprecated forms |
  | `[FAQ]` | `user-documentation.template.md` | A markdown link (`[FAQ](#frequently-asked-questions)`), not a fill-in |
  | `${{ github.* }}`, `${{ secrets.* }}`, `${{ env.* }}`, `${{ matrix.* }}` | `ci-cd-security.template.md` (25), plus every GitHub Actions example | **Mandatory GitHub Actions expression syntax.** Not convertible — `${{ … }}` is the only form the runner accepts. 25 instances in `ci-cd-security.template.md` alone. |
  | `${value}`, `$labels.*` | `monitoring-playbook.template.md`, `deployment-guide.template.md`, `cloud/aws/kubernetes/deployment.yaml` | Prometheus annotation templating. Single-brace precisely so it does **not** collide with the `{{ }}` fill-in namespace — see the collision note below. |

  Two further classes stay, and unlike the ones above they *are* counted by the
  ratchet — they are discounted through the `must_stay` list in
  `scripts/template-marker-baseline.json`, where each carries its reason:

  | Token | File | Why it stays |
  |-------|------|--------------|
  | `[P]` | `tasks.template.md`, `plan.template.md` | The parallel-execution flag in the format grammar, defined literally in the file as `## Format: \`[ID] [P?] Description\``. Names no slot. |
  | `[NEEDS CLARIFICATION…]` | `spec.template.md` | The status flag an author marks on an unclear requirement. |
  | `[Category]` | `srs.template.md` | Metavariable in the NFR id pattern `NFR-[Category]-XXX`. |
  | `[0, 4, 8, 12, …]` | `design.template.md` | A real YAML flow sequence in front matter — the concrete spacing scale. Converting it makes the front matter parse as a string. |
  | `[GITHUB_ACTIONS \| …]`, `[STANDARD \| HIGH \| CRITICAL]` | `ci-cd-security.template.md` | The permitted values of a pipeline and a security-level field. |
  | `[H/M/L]`, `[Low/Medium/…]`, `{Low/Med/High/Critical}`, `{Small/Medium/Large}` | `security-assessment.template.md`, `threat-model.template.md` | Rating scales. A token that enumerates its own permitted values is defining the field, not filling it. |
  | `[User data, financial data, …]` | `security-assessment.template.md` | Worked examples of what *could* go in a threat cell. They illustrate the slot; they are not it. |
  | `[Continue adding ideas…]` | `brainstorming.template.md` | Instructional prose meaning "keep writing", not a slot. |

  A `must_stay` entry is still **counted and then discounted**, so an allowance
  can never hide real debt in the same file. The gate also rejects a `must_stay`
  key that names no measured template, because a mistyped key discounts nothing
  and is indistinguishable from an allowance that has already been applied.

  **The `{{ }}` namespace collides with other tools' templating, and the
  validators cannot tell the difference.** `validate constitution` and the OOXML
  validators both match `jinjaTagRE = \{\{.*?\}\}` (`scripts/internal/validate/docx.go:12`),
  so *any* `{{ … }}` in a document is reported as an unfilled fill-in. Three
  foreign syntaxes collided with that and have been rewritten to single-brace
  form, which is also what those tools actually accept:

  | Was | Now | Tool |
  |-----|-----|------|
  | `{{ $value }}` | `${value}` | Prometheus (`- alert:` / `annotations:`) — `{{ $value }}` was not valid Prometheus syntax at all |

  GitHub Actions cannot be rewritten this way and is exempted by the table
  above instead. **When adding a new example of any templated tool, check it
  against `jinjaTagRE` first** — a `{{ }}` in an example is indistinguishable
  from a fill-in the filler was told to replace.

  A value enum like `{web_app\|mobile_app\|...}` was the fourth form and had no
  canonical equivalent: a pipe inside `{{ }}` splits a markdown table cell. It
  is now written `{{PROJECT_TYPE}}` followed by a plain "one of:" list, so the
  fill-in is checkable and the values are still readable.

  Conversion was not one regex over the tree. `[X](url)` is a markdown link,
  `<div>` is HTML, `{` and `}` are JSON and Go template syntax, and a type
  annotation is indistinguishable from a fill-in by shape alone. Each form was
  therefore converted against an explicit allowlist, and the counts above were
  measured afterwards rather than assumed.
- When a `{{VAR|default}}` tag appears inside a markdown table cell, escape the
  default's pipe: `{{VAR\|default}}` — an unescaped `|` splits the cell.
- One variable name, one value, everywhere it appears. The
  `constitution.template.md` §2 list is the definition site for every threshold;
  §1 table cells reference the same variable. Two different defaults for one
  variable name is a defect — whichever is filled first wins and the other goes
  stale. If two things genuinely need different values, they need different
  names (`DOC_BAR` and `CLAIM_BAR`, not two `DOC_BAR`s).
- Prose describing an example value is not a fill-in. Write `{{RETENTION_DAYS|30}}`,
  not "e.g. 30 days" — the first is filled and checkable, the second is prose a
  reader may mistake for the template's own value.
- Keep templates skeleton-first: headings, tables, and checklist items over prose. Prose belongs in the filled-out document, not the template.
- Adding a template: give it a unique `*.template.md`/`.template.json` name (no ad-hoc `-template.md` variants), register it in `template-registry.json`, and add a row above.
