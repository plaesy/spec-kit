# Session 2026-10-13: lessons

## Check decisions before adding a CLI verb

A background agent added `plaesy search stats` and `plaesy search reindex`. Both broke
`decisions/search-cli-restructure.md` (stats is global) and
`decisions/search-single-verb-and-e5-index.md` (analyze builds indexes). They were removed.
Before a fork adds any command, it must read the decisions that name that area.

**Why:** a command added without this check had to be removed and its task note corrected.
**How to apply:** grep `.plaesy/decisions/` for the verb and the area first, and put the
result in the fork prompt.

## Mocks must keep the store's ordering contract

`TestParentChild_SeparateSectionsStaySeparate` failed about 1 run in 3. The mock vector
store iterated a Go map and did not sort, while real stores return best-first. Sort the
mock results (with the ID as tie-break) so the test matches the contract.

**How to apply:** run a suspect test with `-count=50` before blaming production code.

## A test can have the wrong input, not the code

`TestCheckBudget_ResetsOnNewDay` used a request whose own estimate (about 1024) exceeded
the 1000 budget, so the refusal was correct. The fix was a smaller request in the test.

## Coverage often needs injection, not new tests

`indexer`, `embedder`, `docindex`, and `reach` only reached 90% after their constructors
or loaders became package variables. Behaviour did not change. Expect this pattern for
any package that loads a model or a network client.

## Hard stops that held

- Paid provider calls (Anthropic API) were never made. They need `--confirm` and cost approval.
- Reranker download and spike were stopped when the user judged the cost unjustified.
- A licence was checked on the official page before relying on it
  (bge-reranker-v2-m3 apache-2.0; Jina CC-BY-NC).
