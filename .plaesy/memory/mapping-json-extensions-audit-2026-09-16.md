## What changed

**New mechanism**: `instructions/mapping.json` entries can now carry an `"extensions"`
array (e.g. `word.extensions = [".doc", ".docx"]`) so an instruction file loads when a
matching file *exists* in the target project, not just when a keyword appears inside
manifest content. Added to `word`, `excel`, `powerpoint` (prompted by: Office docs
don't reliably contain "python-docx"/"openpyxl" text), then generalized during
`/assess` to `csharp` (`.cs`/`.csproj`/`.sln`), `terraform` (`.tf`/`.tfvars`), `sql`
(`.sql`) — files that don't reliably contain their own tool-name keyword either.

Both `scripts/bash/detect-stack.sh` and `scripts/powershell/detect-stack.ps1`
implement this generically (loop over every mapping.json entry's `extensions`, no
hardcoded per-framework extension list in either script) — ps1 reads it directly off
the parsed JSON object; bash extracts `"file"`+`"extensions"` blocks with
`grep -Pzo '"file":\s*"[^"]+"[^}]*?"extensions":\s*\[[^\]]*\]'`.

`detection_rules.scan_locations` in mapping.json was extended with `**/*.ext` entries
for all of the above — these are documentation of the extension-check, not a separate
mechanism the scripts read.

## Bugs found and fixed

1. **Pre-existing bash/ps1 parity gap**: `detect-stack.ps1` scanned `*.csproj` as a
   manifest (via `$manifestFiles`); `detect-stack.sh` never did. Fixed by adding a
   dedicated `find ... -name '*.csproj'` pass (root-level `*.csproj` has a
   project-specific basename, so it can't join the other fixed-name manifest checks).
2. **2 orphan instruction files**, never referenced anywhere in `mapping.json` so
   `detect-stack` could never select them: `how-to-create-agentsmd.instructions.md`
   (fixed — added to `methodologies.agentsmd`) and `agents.instructions.md`
   (see correction below — **not** a bug, don't re-add it).

## Correction: agents.instructions.md must NOT be in mapping.json

Initially added `agents.instructions.md` to `always_load` as if it were a normal
missing-registration bug — **wrong**, caught by the user. `agents.instructions.md` is
the platform **core** template: `scripts/configs/platform.json` →
`mapping.core.value = "instructions/agents.instructions.md"`, copied per chosen AI
platform (CLAUDE.md, AGENTS.md, `.cursor/rules/plaesy.mdc`, `.github/copilot-instructions.md`,
etc.) by `plaesy-init.sh`/`.ps1`'s platform-specific loop — completely separate from
the generic instructions copy / `detect-stack` selective-install pipeline that
`mapping.json` drives. `platform.json`'s `mapping.instructions.excludes` already
excludes it from the generic copy for the same reason.

**Rule**: never add `agents.instructions.md` to `mapping.json` (any category). A
`field_semantics_note`/`excluded_files_note` was added directly in `mapping.json` so a
future audit doesn't re-flag this as an orphan.

## Dead fields documented (not deleted)

Per-entry `patterns`/`triggers`, and top-level `description`/`version`,
`detection_rules.priority`/`case_insensitive`/`deduplication` are **not read by either
script** — verified by grepping both for every field name. Only `file`, `keywords`,
`extensions` matter. `case_insensitive`/`deduplication` happen to already match real
behavior (both scripts lowercase before matching, `sort -u`/HashSet the output) but
aren't switches. Documented via `field_semantics_note` + `priority_note` fields added
directly in `mapping.json`, not removed, since deleting risks losing a future
extension point without evidence nothing else reads them.

## Non-finding: `.plaesy/scripts/**` sync

Copied the updated `scripts/{bash,powershell}/detect-stack.*` into
`.plaesy/scripts/**` during this session to test the installed copy — turned out to be
unnecessary busywork: `.plaesy/scripts*` is gitignored (`git status` shows nothing for
it) and gets fully regenerated by `plaesy init` anyway. Confirms the existing rule in
[[overview-md-file-counts-fix-2026-09-16]] ("always edit `scripts/` source, never
`.plaesy/scripts/**`") — no new rule needed, just re-confirmed.
