# memory.md File Structure counts hardcoded to 0

**Symptom**: `.plaesy/analysis/project.json` correctly reported `documentation: 183`,
but the "File Structure" table appended to `.plaesy/memory.md` by `plaesy analyze`
always showed `Source Code | 0` and `Documentation | 0`.

**Root cause**: `generate_overview_md()` (bash) / `New-OverviewMd` (PowerShell) in
`plaesy-analyze.sh`/`.ps1` never counted files — the table cells were literal `0`
strings, unlike `generate_project_json()` / `New-ProjectJson`, which does the real
`find`/`Get-ChildItem` scan.

**Fix**: added the same file-counting logic (code: `.js/.jsx/.ts/.tsx/.py/.go/.java/.dart`;
docs: `.md/.txt`) inside `generate_overview_md()`/`New-OverviewMd` in the **source**
scripts:
- `scripts/bash/plaesy-analyze.sh`
- `scripts/powershell/plaesy-analyze.ps1`

**Important process note**: first attempt mistakenly edited the *generated copy* at
`.plaesy/scripts/bash/plaesy-analyze.sh` (a `plaesy init` output, gitignored per
`.gitignore:18` `.plaesy/scripts*`). User caught this — reverted, redid the fix in the
actual source under `scripts/`. **Always edit `scripts/{bash,powershell}/*.sh|.ps1`,
never `.plaesy/scripts/**`** — the latter is regenerated by `plaesy init` and any edit
there is silently lost. See [[plaesy-analyze-path-fix-2026-09-16]] for the related
prior bug in the same generator functions.
