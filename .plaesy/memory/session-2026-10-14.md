# Session 2026-10-14

## What happened

- The prompt corpus was read end to end and fixed in several passes: Mode 1 research in
  `assess.md`, revert rules in `fix`, `loop`, `optimize`, the `/create` family, `/spec:design`,
  and the `internet_access` gate text.
- The cloud ultrareview caught a wrong gate command: `plaesy reach doctor` does not exist.
  `reach doctor` was removed on 2026-10-08 (see [search-cli-restructure](../decisions/search-cli-restructure.md)). The health check is
  the top-level `plaesy doctor`.
- The same review caught that `templates/constitution.template.md` still shipped the literal
  placeholder examples `{{VAR|default}}` and `{{DATE}}`. The validator reads both as unfilled, so
  every constitution generated by `/start` failed validation. Those two literals were reworded in
  both template copies.
- The revert rule told agents to "restore from the snapshot" but no step ever created one. The
  rule now names a snapshot folder in the project's gitignored `.plaesy` temp area, filled before the first edit.

## Lessons

- **Verify the claimed command exists before writing it into a prompt.** A prompt that names a
  nonexistent subcommand sends the agent into a false failure. Check with `plaesy <cmd> --help`
  or the source, not from memory.
- **Check the template, not only the generated copy.** Fixing the repo's own constitution hid
  the bug for one project. The shipped template still carried it.
- **The IDE and the gate disagree on lint.** The plaesy gate (`validate markdown`) is the
  authority the tests use. The IDE reports extra style rules (table spacing, list numbering) that
  the gate does not enforce. Say which one a claim is based on.
- **Line length is per physical line, measured in characters.** Confirm with `wc -L` or a
  character count, not by eye in the editor, which wraps long lines visually.
- **Do not delegate research to an external skill when the goal is to beat it.** The user
  rejected a Mode 1 design that handed 3+ facet research to `anthropic-skills:deep-research`.
  Research fan-out now runs inside plaesy through the `researcher` role.

## Later in the session: Nara-first routing and no hard stops

- **Correction:** I cited `agents/nara.agents.md` as the council-protocol source in a rule meant
  for projects that ran `plaesy init`. Those projects only have `.plaesy/roles/nara.md`. Cite the
  installed path, not the source path.
- **Lesson:** the always-loaded file must name the routing entry point. A rule that lives only in a
  scope-loaded file (`role-mapping.md`) is not reached by a fresh session. Check `mapping.json`
  `always_load` before assuming a rule applies.
- **Owner decision:** remove the hard-stop behavior and let Nara decide, with NN-01..07 as the only
  limit. The owner accepted the risk knowingly. Recorded in
  [nara-first-no-stop](../decisions/nara-first-no-stop.md).
- **Lesson:** a rule change touches every file that repeats it. Grep `rule 8`, `hard-stop`, and
  `ask` across `instructions/`, `prompts/`, and `agents/` before saying it is done. Commands with
  their own copies (`.claude/commands/`, untracked) need `plaesy init` to refresh.

## How to apply

Before writing a CLI command into a prompt, run it with `--help`. Before calling a template fixed,
generate a constitution from the template and run `plaesy validate constitution` on it.
