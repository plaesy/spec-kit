# Create New Feature Script

**Creates a numbered feature branch and spec directory for Plaesy Spec-Kit projects.**

## Purpose

Given a feature description, the script determines the next sequential feature number, derives a branch name from the description, creates and checks out that git branch, creates `specs/<branch-name>/`, and seeds it with `spec.md` (copied from `templates/spec.template.md` if present, otherwise an empty file).

## Quick Start

```bash
# bash
./scripts/bash/create-new-feature.sh "Add user authentication system"
./scripts/bash/create-new-feature.sh --json "Add user authentication system"
```

```powershell
# PowerShell
./scripts/powershell/create-new-feature.ps1 "Add user authentication system"
./scripts/powershell/create-new-feature.ps1 -Json "Add user authentication system"
```

## Options

| Flag (bash) | Flag (PowerShell) | Effect |
|---|---|---|
| `--json` | `-Json` | Emit result as a single-line JSON object instead of plain text |
| `--help` / `-h` | *(none)* | Print usage and exit (bash only) |
| *(none)* | *(none)* | Any other arguments are joined together as the feature description |

There is no `--number`, `--checkout`, `--no-git`, `--force`, or `--dry-run` option in either script — feature numbering is always automatic and the branch is always created and checked out.

## Behavior

1. Resolves repo root via `git rev-parse --show-toplevel` and ensures `specs/` exists.
2. Scans `specs/` for existing `NNN-*` directories and takes the highest numeric prefix; the new feature number is `highest + 1`, zero-padded to 3 digits (e.g. `001`, `042`).
3. Builds the branch name from the feature description: lowercase, non-alphanumeric characters collapsed to single hyphens, leading/trailing hyphens trimmed, then only the **first 3 words** are kept. Final branch name is `NNN-word1-word2-word3`.
4. Runs `git checkout -b <branch-name>` — this fails if the branch already exists or the working tree can't switch branches; the script does not check for uncommitted changes itself (git's own checkout behavior applies).
5. Creates `specs/<branch-name>/` and `spec.md` inside it, copied from `templates/spec.template.md` if that template exists, otherwise an empty file. No other files (`plan.md`, `tasks.md`, `research.md`, etc.) are generated by this script.

### Branch naming example

Input `"Add user authentication with JWT"` with `specs/002-...` already the highest existing number becomes branch `003-add-user-authentication` (only the first 3 description words are used).

## Output Format

Plain text (default):
```
BRANCH_NAME: 003-add-user-authentication
SPEC_FILE: /repo/specs/003-add-user-authentication/spec.md
FEATURE_NUM: 003
```

JSON (`--json` / `-Json`):
```json
{"BRANCH_NAME":"003-add-user-authentication","SPEC_FILE":"/repo/specs/003-add-user-authentication/spec.md","FEATURE_NUM":"003"}
```

The PowerShell JSON output is produced via `ConvertTo-Json -Compress` and uses the same three keys.

## Integration Example

```bash
# Create the feature, then open the new spec for editing
RESULT=$(./scripts/bash/create-new-feature.sh --json "Add user authentication")
SPEC_FILE=$(echo "$RESULT" | grep -o '"SPEC_FILE":"[^"]*"' | cut -d'"' -f4)
${EDITOR:-nano} "$SPEC_FILE"
```

```powershell
$result = ./scripts/powershell/create-new-feature.ps1 -Json "Add user authentication" | ConvertFrom-Json
notepad $result.SPEC_FILE
```

## Troubleshooting

**"Usage: ... <feature_description>" / empty error** — no description was provided; pass one as the (only) non-flag argument.

**`git checkout -b` fails with "branch already exists"** — a branch with that exact `NNN-word1-word2-word3` name already exists (can happen if you re-run with the same description before the number changes, or after deleting/recreating the same-numbered spec directory). Use a different description or delete the stale branch.

**Not run inside a git repository** — `git rev-parse --show-toplevel` fails; run the script from inside the repo (or a clone of it).

**Feature number reused unexpectedly** — the number is derived by scanning directory names in `specs/`, not by any counter file. If a `specs/NNN-*` directory was deleted, that number becomes available again.
