# plaesy features

The feature-branch workflow: create one, list them, print the current one's
paths, and check it is ready for task generation.

Source: `scripts/cmd/plaesy/features.go` (verb) + `features_create.go` /
`features_paths.go` / `features_validate.go` (subcommands),
`scripts/internal/featurepath/create.go`, `scripts/internal/featurepath/prereq.go`.

| `plaesy features create` | below |
| `plaesy features paths` | [features-paths.md](./features-paths.md) |

> **Renamed.** These were three top-level commands — `plaesy create-new-feature`,
> `plaesy get-feature-paths` and `plaesy check-task-prerequisites` — in three
> different shapes, none of which said they belonged together. All three
> spellings were **removed**, not aliased: they had no deprecation window, and a
> leftover alias would be invisible, since deprecated commands are hidden from
> help and from the documentation bar the drift tests enforce. Update any
> script or prompt that calls them.

## `features create`

### Purpose

Given a feature description, the command determines the next sequential
feature number, derives a branch name from the description, creates and
checks out that git branch, creates `.plaesy/specs/<branch-name>/`, and seeds it
with `spec.md` (copied from `templates/spec.template.md` if present,
otherwise an empty file).

### Quick Start

```bash

plaesy features create "Add user authentication system"
plaesy features create --json "Add user authentication system"
```

### Options

| Flag | Effect |
|---|---|
| `--json` | Emit result as a single-line JSON object instead of plain text |
| `--help` / `-h` | Print usage and exit |
| *(none)* | Any other arguments are joined together as the feature description |

There is no `--number`, `--checkout`, `--no-git`, `--force`, or `--dry-run`
option — feature numbering is always automatic and the branch is always
created and checked out.

### Behavior

1. Resolves repo root via `git rev-parse --show-toplevel` and ensures `.plaesy/specs/` exists.
2. Scans `.plaesy/specs/` for existing `NNN-*` directories and takes the highest
   numeric prefix; the new feature number is `highest + 1`, zero-padded to 3
   digits (e.g. `001`, `042`).
3. Builds the branch name from the feature description: lowercase,
   non-alphanumeric characters collapsed to single hyphens, leading/trailing
   hyphens trimmed, then only the **first 3 words** are kept. Final branch name
   is `NNN-word1-word2-word3`.
4. Runs `git checkout -b <branch-name>` — this fails if the branch already
   exists or the working tree can't switch branches; the command does not check
   for uncommitted changes itself (git's own checkout behavior applies).
5. Creates `.plaesy/specs/<branch-name>/` and `spec.md` inside it, copied from
   `templates/spec.template.md` if that template exists, otherwise an empty
   file. No other files (`plan.md`, `tasks.md`, `research.md`, etc.) are
   generated by this command.

#### Branch naming example

Input `"Add user authentication with JWT"` with `.plaesy/specs/002-...` already the
highest existing number becomes branch `003-add-user-authentication` (only
the first 3 description words are used).

### Output Format

Plain text (default):

```text

BRANCH_NAME: 003-add-user-authentication
SPEC_FILE: /repo/.plaesy/specs/003-add-user-authentication/spec.md
FEATURE_NUM: 003
```

JSON (`--json`):

```json

{"BRANCH_NAME":"003-add-user-authentication","SPEC_FILE":"/repo/.plaesy/specs/003-add-user-authentication/spec.md","FEATURE_NUM":"003"}
```

### Integration Example

```bash

# Create the feature, then open the new spec for editing
RESULT=$(plaesy features create --json "Add user authentication")
SPEC_FILE=$(echo "$RESULT" | grep -o '"SPEC_FILE":"[^"]*"' | cut -d'"' -f4)
${EDITOR:-nano} "$SPEC_FILE"
```

## `features` (list)

Lists every feature directory, ordered by number then name, with the design
documents present in each and `*` on the checked-out branch. A directory that
is not `NNN-slug` is skipped. On a project with no `.plaesy/specs/`, prints the
command to create one rather than an empty block.

**Example**: `plaesy features`

## Troubleshooting (features)

**"feature description is required" error** — no description was provided; pass
one as the (only) non-flag argument.

**`git checkout -b` fails with "branch already exists"** — a branch with that
exact `NNN-word1-word2-word3` name already exists (can happen if you re-run with
the same description before the number changes, or after deleting/recreating
the same-numbered spec directory). Use a different description or delete the stale
branch.

**Not run inside a git repository** — `git rev-parse --show-toplevel` fails; run
the command from inside the repo (or a clone of it).

**Feature number reused unexpectedly** — the number is derived by scanning
directory names in `.plaesy/specs/`, not by any counter file. If a
`.plaesy/specs/NNN-*` directory was deleted, that number becomes available
again.
